**Goal:** a league admin of a private league records what each member paid at `/leagues/{id}/payments` (autosave per row, pots and counts on the server's numbers) and where to send the fee (beneficiary, IBAN, note); every member of a league with a fee sees the dashboard's fee panel (due or paid line, counts and pots, the "Kaip sumokėti" pop-up with three copyable rows, the reward text) and the league's active messages (#29, part 3 of 3). Ends #29.

**Architecture:** The domain owns the money (`Cents` arithmetic, sportbet's number formats, pots under R-88), the `Iban` port, the two posted forms, the two admin decisions and the fee panel's view (R-104). `packages/db` writes each decision in one transaction under the lock order and answers the payments page and the dashboard's league data. `apps/web` answers the autosave with JSON or a real 303 and the details with a real 303 plus a sealed flash, and draws the page, the panel and the messages from components; `/leagues/{id}/payments` joins `GUARDED_PAGES`.

**Tech Stack:** TypeScript, Zod, Drizzle on Postgres 18, Next.js App Router, React, Vitest (unit, db, component, feature), Playwright.

**Spec:** `docs/superpowers/specs/2026-10-12-leagues-design.md` (Split > 12c; "Money is fixed point"; "Addresses"; "A posted id"; "Lock order"; the `paid[memberId]` decision). Rulings R-88 (pots half), R-103 (read in 12a), R-104, R-105, R-116 (messages: read only here); R-87 data only. ## Decisions taken while planning (record them in the spec in Task 19)

1. **Two `RuleSet` fields, nothing else:** `collectedPotLeavesGuestsOut` (R-88: sportbet `collectedPot` sums every member's amount, ruled sums full members only) and `feeDueHiddenFromGuests` (R-104). The expected pot already counts full members only in sportbet. Counts (`Sumokėjo X iš Y`, `Dalyvių skaičius`) stay as sportbet's (Open question 2).
2. **sportbet's answer order, read from the code per action.** `GET payments`: league 404, then `authorizeLeagueAdmin` 403 (public league first, then not an admin). `POST payments` (`UpdateLeaguePaymentsRequest` is a FormRequest, resolved before the controller body): league 404, **validate 422 first**, then 403, then every posted id must be a member of this league (else 404, nothing written). `POST payment-details`: league 404, validate 422 (every field rule, then the IBAN checksum, then both-or-neither, only when no earlier error), then 403. So here, unlike update/invite in 12b, **validate-first** wins over the admin check; a plain member posting a bad amount gets 422, a good one 403.
3. **Money is `Cents`, integers only.** `base_fee` and `penalty_step` are whole euros (`fee * 100` cents in a pot). Text to cents is parsed by string, never through a float. Formats are ported exactly and pinned: the fee line `number_format(fee, 2, ',', ' ')` (`20,00`, `1 234,00`, plain space); the pots `number_format(x, 2)` (`1,234.50`, then `€` with no space); the payments meter the same; the autosave JSON `number_format(x, 2, '.', '')` strings (`collected`, `expected`) plus `paidCount`, `memberCount`; the bar width `min(100, round(collected / expected * 100))` percent, half away from zero, 0 when expected is 0, computed in integers as `floor((200 * collected + expected) / (2 * expected))`; an input's value is `20` for a whole amount, else the decimal with trailing zeros trimmed (`12.5`, `12.55`).
4. **Members on the payments page** are sorted by the lower-cased full name (`trim(name + ' ' + surname)`) compared by code point (PHP `mb_strtolower` then byte order, no Lithuanian collation), ties by membership id; a member with no account sorts as `''`. Display name is the same trimmed string, then the username, then a `Svečias` tag for a guest.
5. **`paid[memberId]` is the posted field** (spec): a member id is read only by `readIdField`-style `idFromText`, keys that are not ids: PHP casts them to 0, no member, so 404 after validation. The amount text is trimmed, `,` becomes `.`, blank is unpaid (null). Rules per amount: numeric, at most two decimals, at least 0, at most 999999.99; `paid` itself required and an array. Each failing rule is listed with Laravel's English message and `paid.<id>` as the attribute.
6. **Autosave answer by `Accept`:** `Accept: application/json` (Laravel `expectsJson`) gets the totals JSON; anything else a 303 to the payments page with the `Mokėjimai išsaugoti` flash. A refused post answers 422 `validationBody` (decision 3 of 12b). The public league is refused on this door (403); its payments are the superadmin's, slice 14, which will pass a `door` to the same writers (not added now).
7. **The fee panel is decided in the domain** (`feePanel`): for a league with `base_fee > 0` (sportbet gates on `session('fee')`, set at sign-in and switch; here read per request, so an edit shows at once), a member who has paid sees the paid line; one who has not sees the due line and the pop-up unless `rules.feeDueHiddenFromGuests` and they are a guest (R-104; the paid line, counts and pots, reward stay). Counts line: `Dalyvių skaičius: <full members>, prognozuojama suma: <expected>€, surinkta suma: <collected>€`. Pop-up: amount `Mokėti <fee> €`, then the three rows when both beneficiary and IBAN are non-blank after trim (`Gavėjas`, `Sąskaita (IBAN)` grouped in fours, `Mokėjimo paskirtis` = `Jaunimo linijai`) and the note, else the `Mokėjimo rekvizitų administratorius dar nenurodė.` text; a paid member gets no rows at all (no account number is assembled for them). No QR (issue 312).
8. **Messages:** the selected league's active messages, in id order, as bold lines; text escaped (React), never HTML. Read only; admin CRUD is slice 14 (R-116). Whether they show for a league without a fee is Open question 1.
9. **Locks:** `savePayments` takes the league row `FOR SHARE` (a delete waits), then the league's members `FOR UPDATE` by player, judged under the lock; `saveDetails` takes the league row `FOR UPDATE`. Neither touches tournament, game or prediction locks, recalculates anything or calls `pointsChanged()`. No throttle (sportbet has none; 12b decision 8).
10. **No new migration.** `paid_cents` and the payment columns exist (12a). `/rules` draws the same `FeePanel` component when its slice lands; this slice wires only `/main`.
