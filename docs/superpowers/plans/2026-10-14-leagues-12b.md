**Goal:** a player manages leagues at `/leagues`: sees theirs and their pending invites, creates a private league, edits it, invites a tournament player found by search, accepts or declines an invite, leaves, deletes, and (R-23) hands a league to another member. The rail's "Lygos" entry and its invites badge arrive with this page (#29, part 2 of 3).

**Architecture:** The domain owns the posted forms (`leagueFormEntry`) and one `Result` decision per action, each taking the `RuleSet` (R-29, R-88). `packages/db` writes each decision in one transaction under the lock order and answers the page and the search. `apps/web` answers each POST with a route handler giving a real 303 and a sealed flash (`Lyga sukurta`, ...), the search with JSON, and draws the page from components; `/leagues` joins `GUARDED_PAGES`.

**Tech Stack:** TypeScript, Zod, Drizzle on Postgres 18, Next.js App Router, React, Vitest (unit, db, component, feature), Playwright.

**Spec:** `docs/superpowers/specs/2026-10-12-leagues-design.md` (Split > 12b, "Addresses", "A posted id", "Search", "Lock order"). Rulings R-20, R-23, R-29, R-88 (search half), R-105; R-25 untouched. Reference: sportbet `LeagueController` (create 76, update 124, invite 151, accept 192, decline 246, searchUsers 300, deleteLeague 412, leaveLeague 463), `routes/web.php:127-138`, `resources/views/leagues/index.blade.php`, `partials/{rail,header,league-switcher}.blade.php`, tests `LeagueMembershipTest`, `LeagueInviteRegistrationTest`.

## Decisions taken while planning (record them in the spec in Task 20)

1. **Two `RuleSet` fields, nothing else.** `lastLeagueCountedPer: 'account' | 'tournament'` (R-29; sportbet counts the player's other leagues anywhere, `LeagueController:478`) and `memberSearch: 'every-account' | 'tournament-players'` (R-88). R-20 holds under both rule sets (sportbet is fixed too); R-23 and R-105 are capabilities with no sportbet rule to keep, so no field. `collectedPotLeavesGuestsOut` and `feeDueHiddenFromGuests` are 12c.
2. **sportbet's answer order is kept as the refusal order.** Update, invite and search check the actor is an admin of that league (`firstOrFail`: **404**, not 403) before they validate the rest; delete is 404 (no league), 403 (not owner), then "public" (so for a public league, which has no owner, the 403 wins: sportbet's "Viešos lygos..." branch is unreachable for delete and kept only in `deleteLeague`'s refusal list); leave is public, owner, only league, then 404 (not a member). Create validates the form before it asks for a tournament.
3. **A posted form answers as 12a's `/leagues/switch`:** the 422 body from `validationBody` (every field's error, Laravel's English messages), as `predictionFormEntry`. sportbet's browser path redirects back with the errors; this app's forms prevent every refusal with `maxlength`/`min` first, as theirs do.
4. **Ids typed into forms and URLs** go through `idFromText` in one `readIdField(posted, attribute)` (generalising 12a's `readLeagueField`): malformed -> 422 `The <attribute> field is required.` / `must be an integer.`; zero, negative or past Postgres' `integer` -> 404 (the 12a follow-up, now for every 12b id: `leagueID`, `inviteID`, `invitedUserID`).
5. **R-20 reads `tournament_players`, not leagues:** "registered for the league's tournament" = a status row there. Equal to sportbet's `isMember` (any membership in the tournament) because 12a puts every player in the public league. Checked in `inviteToLeague` and again in `acceptInvite`; accept leaves the invite pending on refusal. An invitee id that is no account is refused with the same R-20 text (sportbet would 500 on the foreign key).
6. **Selection moves in the writers, in one statement order:** leaving or deleting a league first moves the selection of whoever selects it to the tournament's public league (the composite FK is `NO ACTION`), then removes the rows. A member who accepts is not selected (sportbet `active = false`).
7. **Lock order added to `lock.ts`'s comment:** league row `FOR UPDATE`, then the league's invite row(s), then its members by player, then `lockPlayerStatuses` by player. Accept takes `lockPlayerStatuses(invitee)` before it re-checks R-20, so a deleted account cannot slip in. Invite reads the invitee's status unlocked (accept re-checks).
8. **Throttles:** sportbet throttles no league route. Only the search is limited (`leagueSearchLimits`, 30 a minute per account, spec) because it lists names; no other write gets a limit. League writes change no points: no recalculation, no `pointsChanged()`.
9. **No reader change.** The hub's participant counts already mirror sportbet (12a: card = distinct full members whose selected league is in the tournament; page = distinct full members of any league). 12b adds regression tests to them in tasks 10 (leave, delete, hand over move the card count only through the selection) and 17 (no page reads a stale count).
10. **Search order:** by player id (what MySQL returns for sportbet's unordered query). The fold is `name_fold`, beside `email_fold`, and is never applied to an address; the search matches name, surname or username only, never "name surname".
11. **The navigation:** `NAV_ENTRIES` gains "Lygos" (rail, `trophy`, group `league`, badge `invites`) and "Tvarkyti lygą" (phone menu, `gear`, same href and badge) as sportbet's `rail.blade.php:78` and `header.blade.php:128`; the 12a badge count is now drawn with a page behind it (`nav-entries.test.ts` checks the href has a page).
