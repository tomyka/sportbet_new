# Phase 2.1: Euroleague scoring domain - design

Issue: [#5](https://github.com/tomyka/sportbet_new/issues/5), part of epic #1.
Builds on: `docs/decisions.md` (3, 5, 7, 10, 11), `docs/owner-rulings.md`
(R-1 to R-38) and the rules catalogue
`docs/superpowers/specs/2026-09-29-euroleague-rules-catalogue.md` (rules LR,
MS, CO, FI, SE, SU, ST, RA, PL). The catalogue is the rule text; this spec
says how it becomes code. Where they differ, the catalogue and the rulings
win and this spec is corrected.

## Goal

Every Euroleague scoring rule, as a rich domain model in `packages/domain`
(decision 10), with no database, framework or I/O. Two rule sets, both
first-class:

- **`sportbetRules`** - what produced production's stored points. Used by the
  parity checker (2.3) to prove the port.
- **`ruledRules`** - sportbet plus the owner's rulings. What goes live.

Out of scope: the database and repositories (2.2), the production-copy
reader (2.2), the parity checker (2.3), any page or use case, football
(decision 11).

## The rule set

`RuleSet` is one immutable value object listing every point where the two
sets differ, each named after the rule and ruling it encodes, e.g.
`crowdOddsCountFilledIn` (CO, R-2), `standingsBonusPopulation` (ST, R-3 and
R-36), `positionsGetCrowdBonus` (ST, R-35), `survivalTeamOncePerRun` (SU,
R-11). `sportbetRules` and `ruledRules` are the only two instances. Every
domain method that a difference touches takes the `RuleSet` as a parameter;
nothing reads a global.

- **Why:** the differences live in one reviewable place, each is tested under
  both sets, and a third set (football, a future rule change) is a new
  instance, not a code fork.
- **Turned down:** a second copy of the scoring code (drifts at once);
  booleans scattered through the code (unreviewable); subclassing aggregates
  per set (a rule change would mean a class hierarchy).

## Values

In `packages/domain/src/`:

- **`points/`**: `Points` (exact, fixed-point hundredths - match points are
  always whole or half, MS/CO) and `StandingsPoints` (four decimals, R-31);
  `Odds` (hundredths, after sportbet's double rounding, CO). Arithmetic is
  integer arithmetic on the fixed-point value; no floating-point sum is ever
  stored or compared.
- **Rounding:** sportbet computes crowd odds with PHP floats and `round()` -
  to 4 places, then 2 (CO: `log2(3/2)` must give 0.59; a naive JavaScript
  rounding gives 0.58). The domain has one rounding function that reproduces
  PHP 8.4's `round()` on doubles, and it is proven against a reference table
  **generated by running PHP 8.4** (a throwaway `php:8.4-cli` container, the
  script committed under `packages/domain/test/php-reference/`), covering
  every crowd-odds input shape the catalogue names and the half-way cases.
  Nothing about PHP's rounding is assumed from documentation.
- **`Score`** (home, away, non-negative integers; level allowed only where a
  rule allows it - never for a Euroleague result, R-38), **`Rate`** (positive
  integer), **`TeamId`**, **`PlayerId`**, **`RoundNumber`**.
- Factories validate and refuse (decision 5); an invalid value cannot exist.

## Aggregates and their methods

Grouped by the catalogue's areas; each method's behaviour is the catalogue
rule it cites.

- **`round/` - `Round`, `Game`** (LR): a round has a number, a rate (data the
  admin sets per round, a positive integer; R-10 fixes the values used:
  regular season 1, play-in 1, play-offs 2, Final Four 3, final 3), a stage
  and a survival flag (on for regular-season rounds only under R-10; the
  domain enforces that a non-regular round cannot carry survival under
  `ruledRules`). A game has its
  teams, tip-off time and optional result. `game.isOpenAt(instant)` (LR, the
  lock), `game.withResult(score)` (refuses a level score, R-38),
  `game.reschedule(instant)` (reopens only if not yet locked, R-13).
  `Season.currentRound(instant)` is the round whose next game tips off
  soonest (R-6).
- **`prediction/` - `MatchPrediction`** (MS, FI): real or filled-in (R-1), a
  full score or refused if half-typed (R-15). `prediction.score(game, odds,
  rules)` returns a `MatchPoints` (winner, difference, bingo, odds points,
  full, each at the round's rate - MS rules).
- **`odds/` - `CrowdOdds`** (CO): `CrowdOdds.forGame(predictions, rules)`;
  which predictions count as votes is the rule set's (R-2); missing odds and
  nobody-picked outcomes as CO states.
- **`serija/` - `Serija`** (SE): `Serija.walk(scoredGames, rules)` over one
  player's games in one tournament, tip-off then id order, returning each
  game's streak bonus (running totals, SE).
- **`survival/` - `SurvivalRun`** (SU): `SurvivalRun.fold(picks, games,
  rules)` in round order (R-34), with skips harmless (R-33), postponed picks
  waiting (R-12) and making later totals provisional, once-per-run teams with
  a reset after all 20 (R-11, under `ruledRules`), the tip-off lock (R-4) and
  losses kept as history (R-5). Returns each round's stored value (running
  totals, SU).
- **`standings/` - `StandingsPrediction`** (ST): positions scored flat (190
  exact, 10 fewer per place off, floored at 0), with the crowd bonus on
  positions only under `sportbetRules` (R-35); stage ticks (play-offs, Final
  Four, champion) with the crowd bonus under both, over the population the
  rule set names (R-3, R-36); null vs 0 as ST states.
- **`ranking/` - `LeagueTable`** (RA): one total (match + serija + standings
  + survival, R-18), ranked to the cent (R-31), ties by Lithuanian collation
  (R-30).
- **`player/`** (PL): only what scoring needs - switched off players get no
  fill-in (R-7, R-32); late joiners get fill-ins that are not votes and do not
  count as misses (R-9).

Every aggregate is immutable: a method returns a new value or a result, never
mutates. No aggregate knows about storage (decision 10).

## Error handling

Invalid input (a level Euroleague result, a half score, a rate of 0, a pick
of a used team under `ruledRules`) is a typed refusal returned by the
factory or method (a `Result`-style union), never an exception, so callers -
use cases later - must handle it and the compiler checks they do. Programmer
errors (an impossible state) throw.

## Tests

- **One named test per catalogue rule** (the catalogue lists the test names),
  under both rule sets wherever the sets differ.
- **Golden master.** sportbet's golden scenario
  (`tests/Support/GoldenScenario.php`, `tests/Fixtures/golden-points.json`)
  is expressed once as domain inputs - its 25 Euroleague entries (9 match, 8
  standings, 5 survival, 3 odds), mapped in the catalogue - and must
  reproduce every Euroleague number exactly under `sportbetRules`. Under
  `ruledRules` the same scenario produces the documented differences only
  (the catalogue lists them, e.g. the `ada / OLY` play-off tick 60 -> 120),
  asserted explicitly.
- **PHP rounding reference** as above.
- **Property tests** where a rule has an invariant (running totals never
  decrease within a run; points are always whole or half for match scoring).
- Domain tests are unit tests: no container, no network.

## Structure and lint

- New areas as folders under `packages/domain/src/` (above), each exporting
  through `packages/domain/src/index.ts`; the existing `tournament/` and
  `invariant/` stay.
- The domain lint rule holds (imports only zod and its own files, no dynamic
  imports). A decimal library is not added: fixed-point integers are enough
  and keep the domain dependency-free; if the plan finds otherwise, it adds
  one library to the domain's allowed imports deliberately.

## Done when

Every catalogue rule has a passing named test under each set it applies to;
the golden scenario reproduces sportbet's Euroleague points exactly under
`sportbetRules` and the listed differences under `ruledRules`; the PHP
rounding reference passes; the catalogue's open-questions section records
the answers (R-32 to R-38); CLAUDE.md "Code rules" names the rule-set rule
("a difference between sportbet and the rulings goes in `RuleSet`, nowhere
else").
